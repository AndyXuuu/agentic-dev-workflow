# Agent Workflow Measurement

只测量 Agent 会话和编排效率，不把被讨论的项目功能当成被测对象。

## 对象绑定

首次工具调用前在内部固定一项：

- `agent-session`：Agent/OMP/Orca 会话墙钟、回合和工具开销。
- `project-behavior`：目标项目功能、性能或运行时行为；转到项目 Owner 和 focused 验证。
- `separate`：两者都要，分别建立时间窗和结论，禁止混合统计。

用户提到一个项目问题作为样例，不等于授权调查或测试该业务行为。只有用户明确要求验证产品行为时才进入项目工作流。

## Agent 会话快速路径

单一会话测量问题：

1. 不建立 Todo，不加载目标项目业务 Skill，不运行项目 formatter、lint、测试、构建、全量门禁、部署或生产命令。
2. Orca 管理的工作区先使用 `$orca-cli` 定位当前/近期 worktree、terminal 和持久化会话；已知 session JSONL 时直接读取或一次解析。
3. 最多三个工具波次：定位会话、解析统计、仅在解释机制时读取至多两份 `omp://` 文档。证据已回答问题即停止。
4. 默认不运行 Git inspection。只有区分提交/同步阶段造成的开销时，才从会话记录统计既有 Git 命令。
5. 不读取 secret、`.env`、Token、凭证、原始业务数据或生产日志正文；命令文本和输出先按类型归类再报告。

超出预算只允许因为：目标会话不明确、输出被截断需恢复 artifact、或必须区分 OMP 内建行为与自定义规则。报告具体原因，不转向业务实现调查。

## 指标

从同一时间窗计算：

- 用户请求到最终答案的墙钟时间；区分用户阅读/等待时间。
- Assistant 消息、含工具调用的回合、工具调用总数和工具波次。
- 各工具次数、累计执行时间、关键路径时间；并行调用不得把累计时间误写成墙钟。
- 后台 job、主动 wait/jobs 轮询、空闲间隔和失败重试。
- 项目测试、全量门禁、formatter/lint、Git status/diff、Todo、重复读取次数。
- `wall time - tool critical path` 的非工具编排时间；若只能取得累计工具时间，明确它是上界或下界。

## 判断

按证据区分：

- OMP 内建机制：上下文注入、Skill 暴露、后台 job、Todo 状态和提醒。
- 全局自定义规则：Fast Path、primary workflow、验证和交付门禁。
- 项目规则：Owner、命令、发布或环境限制。
- Agent 自主选择：误路由、重复读取、重复验证、轮询和过长回答。

不要因为存在项目测试命令就运行它。不要用产品行为测试替代会话统计。

## 输出

先给：

1. 总墙钟时间和是否符合预期。
2. 工具执行时间与非工具编排时间。
3. 调用/回合/测试/门禁/轮询统计。
4. 违反或正确执行的具体规则。
5. 最小理想路径、目标工具波次和预期节省。

所有时间和命令次数必须来自 session、terminal 或 job 记录；推断标记为 `[INFERENCE]`。
