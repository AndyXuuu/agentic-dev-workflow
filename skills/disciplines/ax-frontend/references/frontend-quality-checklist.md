# 前端质量检查表

## 视觉与设计系统

- 已读取项目视觉标准和相关组件/Token owner。
- 审查任务已记录分支、HEAD、工作树状态、时间和报告新鲜度；审查期间的仓库变化已重验或限定结论快照。
- Token 定义、组件实现、权威展示/文档和生产消费保持一致；设计系统治理任务已按 `design-system-governance.md` 取得证据。
- 疑似缺失 Token 已区分项目定义、框架默认、运行时注入、生成/环境来源和 fallback，未把静态未知项误报为确认缺失。
- 已复用语义 Token、组件变体、字体、图标和资产管线。
- 没有散落项目禁止的 raw color、magic number、arbitrary value 或外部资产 URL。
- 新全局/共享 Token 具有跨组件或跨场景语义；组件私有 Token 具有稳定组件语义；一次性场景值未被错误提升。公开 Token/变体已更新权威展示或文档。
- 共享组件覆盖其实际契约和风险相关的变体、交互状态、数据状态、主题与响应式行为；未机械补齐不存在的全量状态矩阵。
- 对稳定共享库，公开组件清单来自 export、稳定入口、文档和消费者证据，并具有与成熟度匹配的真实示例、契约测试或明确豁免；单应用局部组件不强制采用公共库治理。
- 生产页面的共享组件、Token 和资产采用情况已通过代表性页面追踪或项目自动化门禁验证；允许的局部实现有明确理由。
- 代表性页面抽样覆盖主要领域与风险，记录了选择理由、停止条件和未验证消费者。
- 设计系统目录若被通用检查排除，已有等价或更严格的专用检查；排除范围和替代证据均可追踪。
- Light/Dark/高对比度等项目支持主题均保持正确。
- 主题、组件样式或交互定制后，已重新验证实际暴露的状态、对比度、焦点、目标尺寸和行为，未假设底层组件库的合规性会自动继承。

## 组件与职责

- 遵循项目现有表现层边界；页面/场景/基础组件、组件库、Widget、微前端或无路由入口没有被强行改造成另一套分层。
- 视图输入/输出契约窄且明确，没有泄漏传输层或第三方 SDK 类型。
- 业务规则、权限、定价、格式化、校验和状态机位于已有 owner。
- 相同行为复用或抽取；刻意差异有明确理由。
- 文件、组件和函数职责单一；超出项目规模阈值时先检查职责混合、依赖扇出、隐藏副作用、变更局部性和可测试性，只有存在可验证的独立边界时才拆分。

## 状态与交互

- 远端数据按相关性覆盖 Loading/Skeleton、Data、Error、Empty。
- 控件覆盖相关的 default、hover、focus-visible、active、disabled、loading、error。
- Mutation 防重复提交，并定义成功、失败、取消、超时、部分成功和恢复。
- 错误没有被吞掉；用户得到可行动信息，日志保留 cause 且不含敏感数据。
- 输入约束按规范化后的业务值判定；明确前后空白是保留、裁剪还是拒绝，并覆盖空字符串、纯空白和相关格式错误，不能只依赖 `required`、`type` 等原生约束的表面合法性。
- 反馈强度与风险、等待时间和恢复成本匹配：字段错误就地关联，页面已有清晰可见结果时不重复 Toast，长任务显示状态并在可取消时提供取消。
- Dialog 只用于重要、可行动且确需阻断的反馈，不替代普通状态、成功提示或就地错误。

## 响应式与内容

- 从最窄受支持视口逐步增强，不依赖单一固定尺寸。
- 在项目或宿主声明的最窄支持宽度下检查 Reflow；通用 Web 页面没有更明确契约时可用 320 CSS px 等效宽度（或 400% 缩放）校验，主要任务无需双向滚动，二维内容等 WCAG 允许例外除外。
- 文本放大到 200% 后内容和控件不丢失、不重叠且仍可操作。
- 检查长标题、翻译膨胀、空字符串、大数字、多行错误和动态列表。
- 图片/视频保持比例、裁切、加载、fallback 和错误行为。
- Overlay、Dialog、Sheet、Menu 正确处理滚动、所属视口/包含块、返回/关闭和焦点恢复；嵌入场景已区分 Widget/iframe 与顶层宿主可控制的边界。
- 存在路由或导航契约时，深链、刷新、返回和必要的 URL 状态保持一致；无路由入口不机械执行页面导航检查。

## 可访问性

- 目标至少为 WCAG 2.2 AA，除非项目要求更高。
- 使用语义 HTML；button、link、input 不用可点击容器替代。非语义交互按下述统一定义判定。
- 表单具有 Label、说明、错误关联和合理 autocomplete。
- 键盘可到达、可操作、可退出；焦点顺序符合视觉顺序。
- `focus-visible` 清晰，颜色不是唯一状态信号，文本与控件对比度达标。
- Web 指针目标满足 WCAG 2.2 AA 的 24×24 CSS px 最小尺寸，或符合间距、同段文本、等效控件等适用例外；项目或平台要求更严格时从其规定。
- 触控优先场景的重要目标宜约 44×44 CSS px，并保持足够间距；这是平台/场景建议，不作为所有 Web 控件的统一失败门槛。
- 图片有正确 alt；装饰内容不进入辅助技术语义。
- 动画尊重 `prefers-reduced-motion`，不依赖运动传达唯一信息。
- 优先复用组件库的 Dialog/Menu/Popover 焦点和 ARIA 契约。

### 非语义交互门禁定义

- 判定对象是用户最终获得的 DOM、可访问性树和键盘行为，不是 JSX/template 调用点的组件名称，也不是是否出现某种点击/激活回调语法。
- 原生 `div`、`span` 等非交互元素直接承担点击、键盘激活或导航行为时，判为非语义交互；应优先改用原生 `button`、`a`、`input` 等正确元素。
- React/Vue/Svelte/Angular/Web Components 等框架组件接收点击或激活回调，只能说明它暴露了交互契约，不能直接判为违规。若组件 Owner 稳定渲染正确的原生交互元素，并满足名称、键盘、焦点和禁用语义，则调用点合规。
- 对多态根节点、动态组件、slot/asChild、条件模板或其他无法在调用点静态确认最终 DOM 的实现，标记为“语义待验证”，追踪组件 Owner、类型/模板约束或渲染测试；未取得证据前既不计入确认违规，也不标记通过。
- 仅用于事件传播控制、指针区域辅助或其他非用户命令语义的处理器，不得仅凭回调名称自动计为交互控件；仍需确认存在独立、可访问的主操作和等价键盘路径。
- 自动化门禁分别报告“已确认非语义交互”和“语义待验证”，并提供 Owner/文件证据。只对目标项目真实使用的 JSX、Vue/Svelte template、Angular template 或自定义元素语法启用对应静态规则；跨组件结论来自实现、受控语义组件清单、类型/模板约束或渲染测试。
- 项目存在此类静态门禁时，门禁回归至少覆盖：原生语义元素合规、原生非交互元素承担用户命令违规、已知语义包装组件合规、动态/多态根节点待验证，以及纯传播控制不被误判。

## 数据、安全与平台边界

- UI 通过现有 client/query/adapter 获取数据，不直接拼接未验证请求。
- 输入、权限和身份在可信系统边界校验；前端隐藏不等于授权。
- 不可信 HTML、Markdown、富文本、URL、文件名和跨窗口消息在进入 DOM、导航、下载或命令边界前按项目策略校验/清洗；绕过框架转义的 API 具有明确 Owner、审查和测试证据。
- `postMessage` 校验预期 `origin`、发送窗口/宿主身份和消息结构；客户端存储不承载超出威胁模型的长期敏感凭据；Blob/Object URL、订阅和事件监听在生命周期结束时释放。
- 浏览器 API、时间、随机数和存储不会造成 hydration 不一致。
- 新浏览器/CSS API 符合项目支持矩阵，并按既有策略提供 polyfill、fallback 或 progressive enhancement；WebView、扩展、嵌入式宿主和跨源限制相关时已验证。
- 外部调用有项目定义的 timeout；重试有界、退避，并考虑写操作幂等。
- 不硬编码或记录密钥、令牌、个人数据、支付数据和敏感 URL 参数。
- 分析事件复用既有 schema，避免重命名或重复计数。

## 性能（按改动相关性）

- 已识别项目现有性能预算、RUM/Web Vitals、Bundle、图片和字体策略；没有自行发明与项目无关的固定阈值。
- 改动影响启动、导航、渲染、交互、资源加载或大数据量时，检查相关的 LCP、CLS、INP、长任务、重复渲染、Hydration、代码分割、缓存和资源优先级风险。
- 大列表、复杂图表、编辑器或高频更新只在数据规模证明需要时采用分页、虚拟化、增量计算或 Worker；不为假设性能问题预建复杂度。
- 性能门禁按项目 Owner 和触发条件运行；没有把本地单次测量或开发模式结果写成生产性能结论。

## 工程与交付

- 没有无用 import、变量、样式、日志、注释代码或临时文件。
- 用户可见文案进入现有 i18n owner，代码注释解释 why。
- 测试断言用户行为和契约，不镜像实现细节。
- Bug 具有修复前后同一失败证据；永久回归测试已通过 Test Admission Gate。真实布局、动画或兼容性无法由当前测试环境可靠断言时，使用浏览器/E2E/视觉证据并记录未自动化理由。
- 已按风险和项目成熟度选择最小充分的契约测试、静态检查、视觉回归与浏览器验证；未把 Storybook、全量状态截图或视觉回归作为所有项目的默认门禁。
- 已区分本地 focused 行为检查、按风险触发的整体/集成检查和 CI/发布门禁；每层均有真实结果或明确 Owner/延后理由，未把未运行项暗示为通过。
- 新增或调整重型依赖、动态导入或构建分包时，已检查生产构建的 chunk、重复依赖和懒加载边界；未把固定体积阈值机械施加于无相关变化的任务。
- 已手动检查目标界面、入口或宿主环境的视口、主题、键盘、状态和控制台；本次触达的 Overlay 已真实打开，并按契约检查居中或锚定位置、所属视口/包含块内的完整包含、安全边距、Backdrop、层级、滚动和焦点，嵌入场景已记录顶层宿主不可控制的边界。
- 浏览器自动化的 `clicked`、`pressed` 等命令回执已由 DOM、可访问性树、焦点、URL 或业务状态变化补证；回执与结果不一致时已区分工具注入失败和产品缺陷，并保留替代证据或未验证声明。
- 已更新现有权威文档并报告风险、未验证项和回滚方式。
